# Результаты стенда

Каталоги содержат свидетельства проверок, измерительные серии и архивы среды. Их имена и наличие отчёта сами по себе не означают успешный эксперимент: смотрите admission, исходы, проверки и ограничения конкретной серии.

| Каталог | Назначение |
|---|---|
| [main/](#main) | Подготовленные и исполняемые основные серии |
| [verify/](#verify) | Проверочные, диагностические и интеграционные запуски |
| [archives/](#archives) | Архивы Docker-образов и свидетельств с контрольными суммами |

В серии встречаются `schedule.json` (назначения), `ledger.json` (учёт блоков), `admission.json` (допуск), `snapshot/` (снимок среды и исходников), `outcomes.json` (исходы), raw и частичные данные, `derived/` (производный отчёт). Конкретный набор зависит от этапа и версии стенда.

Сохранённые raw, снимки и исторические статусы не редактируются при обновлении кода или документации. Повторный анализ создаёт производные данные: `make analyze SERIES=results/main/имя-серии`. Подробности — [анализ](../docs/analysis.md), [возобновление](../docs/run.md).

<a id="archives"></a>

## Архивы среды и свидетельств

`make archive` сохраняет четыре Docker-образа в `images-<sha256>.tar` и создаёт рядом `.tar.sha256`. Они предназначены для автономного переноса среды. Архивы `stage3-*-evidence.tar.gz` сохраняют свидетельства соответствующего этапа; рядом находятся контрольные суммы.

Большие `*.tar` исключены из Git, поэтому после клонирования могут быть доступны только их контрольные суммы. Подпапок нет. Скрипт создания — [archive.sh](../docker/commands/archive.sh), контекст результатов — [results/](README.md).

<a id="main"></a>

## Основные серии

Каждая подпапка — отдельная подготовленная серия с собственными расписанием, допуском и снимками. Подготовка ещё не означает начало или завершение сбора. Текущий путь создаёт каталог через `make exploratory-prepare`; выполнение запускается отдельно через `make experiment`.

Имеющиеся каталоги:

| Каталог | Содержимое |
|---|---|
| [final-20261115/](main/final-20261115) | Артефакты серии с этим идентификатором |
| [final-20261115-layout/](main/final-20261115-layout) | Артефакты серии и сохранённый снимок исходников |
| [final-develop-20261115/](main/final-develop-20261115) | Артефакты серии и сохранённый снимок исходников |

Для состояния конкретной серии смотрите её `admission.json`, `outcomes.json` и `derived/report.md`, если они созданы. Имена каталогов не обозначают результат проверки. Новые серии получают новые каталоги; сохранённые снимки не обновляются вслед за рабочим кодом. Порядок запуска — [docs/run.md](../docs/run.md).

<a id="verify"></a>

## Проверочные запуски

Свидетельства проверки отдельных частей стенда. Внутри групп каталоги относятся к конкретным запускам и версиям среды; исторические failed, partial и not_run сохраняются.

| Каталог | Назначение |
|---|---|
| [acceptance/](verify/acceptance) | Проверки допуска |
| [analysis/](verify/analysis) | Проверки анализа и статистики |
| [build/](verify/build) | Свидетельства сборки |
| [diagnostic/](verify/diagnostic) | Диагностика генератора и среды |
| [environment/](verify/environment) | Проверки среды выполнения |
| [integration/](verify/integration) | Интеграционные проверки |
| [interop/](verify/interop) | Совместимость транспортов и TLS |
| [measurement/](verify/measurement) | Короткие измерительные серии |
| [path/](verify/path) | Проверки сетевого пути |
| [raw/](verify/raw) | Проверки исходных измерений |
| [readiness/](verify/readiness) | Этапы готовности, калибровки и контрольных сравнений |

Состояние определяют отчёты и документы проверок внутри запуска, а не имя каталога. Эти артефакты не заменяют основные серии в [main/](#main). Команды и область применимости — [docs/verification.md](../docs/verification.md).
