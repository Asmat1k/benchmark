# Передача R2

Прежняя инструкция handoff.md сохраняет историю первой версии. Обновлённый docker/collect-diagnostic.sh публикует один results/verify/diagnostic/<последняя-серия>-report/report.json для каждого gate. Генератор требует четыре запуска WS/WT-S × 20/100 Гц. Команды вызова и постоянный SERIES_TLS_DIR остаются прежними. Отдельный отчёт одной стороны не допускается к публикации как реальный generator.

Положительная привязка требует исходного расписания, полученного из фиксированных параметров и имени серии, завершённого ledger, совпадения каждой строки с выбранным manifest, полного совпадения опубликованного snapshot с расписанием. Существующая validate_raw проверяет локальный context и фактические ресурсы; сборщик сопоставляет этот context с запрошенным ENV, повторно извлекает первичные слоты и делит CPU на лимиты из raw. При прямой публикации и полном повторном verify заново восстанавливаются значения из указанных первичных каталогов. Проверка идентичности режима/запуска требуется дополнительно к существующей validate_raw, которая ищет строку расписания по manifest.

Тест с копией реального smoke принимает совпадающий manifest, отклоняет иной mode и изменённый snapshot. Контрпример с изменённым ограничением CPU в ENV по-прежнему отвергает существующая validate_raw; повторное вычисление context_snapshot в адаптере было бы избыточно. Пары только одного режима недостаточно. Синтетические прежние тесты пар частот без mode сохраняют свой контракт. Запуск generator-измерений в этом исправлении не проводился.

Первая попытка generator-r2-tests использовала smoke с ненулевой добавленной задержкой и получила ожидаемый отказ в baseline-only адаптере; тестовую основу заменили принятой baseline-копией. Финальная проверка 5/5. Файлы ../host/generator-r2-final.json и ../host/generator-r2-timer-replay.json включают UTC, команду, время, exit, пути и SHA256 журналов. Второй запуск лишь повторно извлекает 100000 интервалов из сохранённой страницы прежней версии. Замороженные файлы переданы verifier по R2-SHA256SUMS.
