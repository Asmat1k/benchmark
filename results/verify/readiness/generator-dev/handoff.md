# Диагностика таймера и генератора

Исполнитель `/root/generator`, запрос model/effort — inherited, подтверждённые значения неизвестны. Исходный HEAD aeda8e1d36bc5bc87042a6e497eefaf84213397e. Список исходников и их SHA256 находится в SHA256SUMS.

Перед сбором пересобрать browser с новым measure.ts, выбрать один постоянный SERIES_TLS_DIR с доверенным CA, действительным leaf и pins для всех связанных фаз, проверить SHA, реальные image IDs и остаточный срок. Штатный testcert создаёт leaf на 13 дней от текущего времени минус минута. Отдельный временный smoke автоматически удаляет свои ключи. Ключи в каталог evidence не копировать. Каждый запуск D3 связывает фактический хост, VM, образы, leaf, конфигурации и ограничения в context.json. Сборщик проверяет совпадение исходников при сборе и при формировании входа. Состояние Git каждого прогона остаётся в manifest.json. Проверка чистого зафиксированного релиза AA и последующих стадий сохранена.

Из корня на одном хосте с указанным абсолютным SERIES_TLS_DIR:

1. `sh docker/collect-diagnostic.sh timer` создаёт новую короткую D3 smoke-серию в results/verify/diagnostic/. На первой защищённой странице получаются 100001 значение performance.now, соответствующие 100000 разностям. Итог появляется в отдельном каталоге с суффиксом -WS-report, имя выводится в stdout. Для последующих отчётов использовать тот же путь context.json этой серии.
2. После успешных ранних проверок и калибровки `sh docker/collect-diagnostic.sh generator results/verify/diagnostic/<timer-series>/context.json` выполняет две baseline-серии, по одному полному блоку обоих обязательных режимов на каждой из двух частот. Интервал задаёт только диагностическое расписание. На режим получаются 200+1200 плановых слотов при 20 и 100 Гц. Результаты WS и WT-S проверяются раздельно по штатному generator_gate. Любой ненулевой exit блокирует продвижение. Два отчёта и первичные данные сохраняются независимо от результата научной проверки, при прерывании D3 сохраняет STOP/quarantine. Частота, лаг, CPU/лимит, throttling, OOM и backlog берутся из сырых записей. Размер очереди и накопленные drops опрашиваются примерно раз в секунду, без утверждений о пропущенных между отсчётами пиках. Длительность самой нагрузки генератора около 168 с на оба режима, дополнительно нужны развёртывание четырёх сред, сбор и проверка.
3. Локальные сети Compose и неизменные raw ведёт docker/measure.sh; к окончанию каждого прогона он останавливает свою среду. При перезапуске создать новый сбор и сохранить причину. Для официальных AA/monitoring/pilot остаются штатные admission.
