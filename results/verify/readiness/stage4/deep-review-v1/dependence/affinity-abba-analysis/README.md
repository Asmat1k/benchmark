# Affinity ABBA: результат inconclusive для исправления

Источник: `results/verify/diagnostic/affinity-abba.lK9trsns`. Исполнитель проверки: Codex dependence_review. Это read-only разбор уже завершённого фиксированного r80p1 ABBA; новые сетевые или тайминговые опыты не запускались. Анализ в network-none контейнере занял менее секунды, общий предел команды 90 секунд.

## Корректность и реальная CPU-политика

Проверены все **82 sealed файла**, равенство source snapshots до/после и стандартный pcap/ID/tag/drop accounting. В каждой подсерии ровно 5000 последовательных sent ID, 4901 уникальный полный reply ID; forward entered5000/drop56, reverse entered4944/drop43. Capture kernel drops0. Все четыре набора потерь совпадают по предусмотренной политике одинаковых seeds; это сопоставимые common-random-number условия, а не четыре независимые реализации loss.

Actual Docker `HostConfig.CpusetCpus` и `/proc/1/status:Cpus_allowed_list` совпали:

- shared-A1/A2: sender helper и echo-server helper оба `0-1`;
- pinned-B1/B2: sender helper `0`, echo-server helper `1`.

Не предполагаем affinity по одному имени серии: маски проверены в каждом сохранённом inspect/status.

## Критерий решения

Предварительный план требует согласованного улучшения B1/B2 относительно A и предписывает inconclusive, если A и B оба clear либо результаты смешанные. Здесь **оба A тоже clear**, проблемный переход r80p1 не воспроизвёлся. В последнем A2 RTTp99 лучше обеих B; max sender lag в B выше обоих A, хотя остаётся в допуске. Это не согласованное улучшение.

**Affinity как исправление не подтверждена. Результат — inconclusive; добавлять CPU pinning в production как доказанное исправление не следует.** Реальные маски корректны, то есть отрицательный результат нельзя объяснить тем, что treatment не применился.

Poll0 во всех четырёх условиях одинаков; этот опыт не отменяет его предыдущего положительного ABBA по ожиданию. Но здесь нет нового доказательства устранения редких129мс пауз или возможности принятия полной калибровки. 50сек на подсерии, всего100сек condition exposure, не заменяют10000-ID формальные подсерии и14+4 полный сбор. Историческая failed калибровка остаётся failed, thresholds/RTT/блоки не корректировались.
