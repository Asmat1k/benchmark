# Независимая сверка результатов реализации

14 ноября 2026, внутренний сабагент method_review. Проверка выполнена после implementation/regression.exit=0 (30 тестов). Это exploratory применение нового метода к прежним данным, не новая подтверждающая калибровка и не изменение исторических failed/reports.

## Выполнение и входы

`execute.py` запустил pinned analyzer image sha256:9e263785dc135db52a216bc358c38218cf3d98f178a9981a365ca79cda7cbd62 в Docker с --network none, одним CPU, timeout120. Фактически 4.395 s, exit0, stderr пуст. Точные argv/cwd/UTCstart/end/exit находятся в execution.json; stdout.log и exit сохранены отдельно. Новых сетевых сборов не было. Недостающий локальный numpy обойдён использованием предусмотренного analyzer image; executable production code не редактировался.

Прочитаны все 42 echo-серии calibration.lShojabe, calibration.gIdWLx7o и calibration.ew2u0ceD. Проверены все 438 ссылок captured.json по SHA256. Для каждого файла новой реализации и старого shadow.py/json сохранены SHA256 в derived.json; проверено отсутствие изменения этих источников во время вычисления.

## Независимый расчёт

Предикаты рассчитаны по исходным timestamp/RTT через Decimal, отдельно от float-пути новой реализации. Rolling counts рассчитаны deque-накоплением без её prefix-sum функции. Сравнены все четыре ряда счётчиков для всех 168210 phase windows (42×5×801), а также все максимумы фаз с сохранённым shadow.json. Отдельно проверены все 360 median окон (3×6×20) через statistics.median и исходные ID, включая число вернувшихся RTT. Расхождений нет.

Лаговые максимумы на прогон составляют 3/0/1 отмеченных слотов в 1200-слотном окне; максимумы joint timing на loss0 — 6/1/3, что совпадает со старым shadow. Новая sender_check даёт exploratory passed всем 42 сериям; это только результат конкретной функции при новой политике, не приёмка полного calibration gate, не prospective validation и не переписывание прежних отказов.

Все loss0 серии имеют 10000 вернувшихся RTT и joint_deadline_complete=true. На loss1 missing остаются в явном учёте: от 183 до 249 на серию, неизвестный timing outcome в окне — до 44/1200. Поэтому известные timing-bad counts на loss1 являются нижними границами, а не полной совместной deadline проверкой. Счётчики unknown сохранены для каждого окна; их нельзя интерпретировать как своевременные ответы. Ни одного missing RTT не заполняли и ни одного медленного RTT не исключали.

## Контрпримеры и граница

Синтетический один эпизод на ID5000, catchup2.5ms, RTT.6ms:

| Пауза | Максимумы bad по фазам | Результат новой sender_check |
|---|---|---|
| 499 ms | 12/12/12/12/12 | passed |
| 500 ms | 13/12/12/12/12 | failed |

Оба результата совпадают с заранее описанной границей. Синтетика помечена отдельно в derived.json и не выдается за измерение. Это ограничение доли отмеченных proxy-слотов, не максимальной паузы, не фактический replay браузера и не доказательство границы влияния на Q/S/U.

Проверка не запускает bootstrap и не исследует заново чувствительность 57600 браузерных synthetic сценариев. Она проверяет именно согласованность новой реализации с сохранённым shadow и независимой арифметикой на всех сохранённых исходных коллекциях. Для завершения этапа4 по-прежнему нужны новый source-bound план, одна будущая подтверждающая калибровка, применимые integrity/review и остальные prerequisites.
