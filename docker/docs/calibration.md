# Диагностический UDP-сбор

Из корня принятого релиза выполнить `SERIES_TLS_DIR=/absolute/path/to/tls sh docker/commands/calibration.sh` после build/TLS/path/raw/analysis/timer. Требуются закреплённые роли и свободные обе лабораторные подсети. Каталог TLS должен содержать leaf принятой среды. Коллектор удерживает общий measurement lock. Ожидается 14 серий по 102 с и четыре нагрузки по 72 с, суммарно около 30–35 минут, ориентировочно до 350 МБ. Владельцу Docker-контекста требуется доступ к его локальным контейнерам. Каждый запуск создаёт отдельный каталог results/verify/diagnostic/calibration.*.

Перед пробами коллектор закрепляет permanent neighbor entries между router и обоими endpoint по фактическим MAC созданных veth. В каталоге сохраняются четыре JSON-снимка ip neigh. Это устраняет обновления ARP, которые иначе попадают под общий netem и смешивают drops управляющих кадров с потерями UDP. Строгая сверка UDP-потерь со счётчиками tc сохраняется.

Проба использует сетевые пространства имён browser/server и два дополнительных процесса Python в отдельных контейнерах с закреплённым образом analyzer. На этом этапе исследуется маршрут UDP, CPU этих дополнительных процессов не измеряет запас браузерного генератора. Время RTT измеряется на одном monotonic clock отправителя. Для каждого эхо сохраняются реальные ID и времена отправки/возврата. До и после четырёх профилей измеряется baseline. Для вывода RTT каждый профиль имеет собственную подсерию `*-latency`. Для потерь по каждому профилю выполняют две отдельные подсерии, до и после сбора RTT. Каждая получает собственную пару seeds и идентификатор с именем запуска и подсерии. Его метка (первые 8 байт SHA256) передаётся в каждой датаграмме и сверяется с обеими pcap и журналом отправителя. Разнонаправленные последовательные seeds зафиксированы до измерений. Временную структуру проверит UDP sender v2 из configs/thresholds.json: late≥10мс ≤1%, max lag≤50мс и ≤4 пакетов/окно10мс; прежний every-slot остаётся в отчёте. ID и фактические потери сверяются отдельно без ослабления целостности. [Обоснование и qualification](../docs/readiness/sender-quality-v2.md). Исходные массивы сохраняются даже при нарушении сетки. Каждый ingress router пишет pcap с Ethernet, IPv4, заголовком UDP и ID. Потери вычисляются по фактическим ID, сверяются с разностью счётчиков drops на соответствующем qdisc. Несовпадение требует разбора первичных данных и блокирует публикацию. Переполнение получателя нельзя записать как потерю netem.

Saturation подаёт UDP payload 1200 байт с интервалом 800 мкс. Единица скорости — байты, снятые с netem на выходе (skb, включая Ethernet), за измеренное центральное окно 61 с по uptime VM. Одновременно берётся разность rx_bytes входного veth. Проверить airtime нагрузки по probe.json, обе границы очереди по window.txt, стабильное состояние после дренирования и ожидаемую очередь при намеренном насыщении. В скорости не учитываются FCS, preamble и межкадровый интервал.

Методика этого релиза — [circular-block-medians-v1](../docs/readiness/calibration-blocks-stage2.md). collection-plan.json сохраняется до запуска сети и проверяется packager. В review дополнительно обязательны assumptions.stationarity/short_memory/bernoulli_loss (непустые обоснования) и trace_review.stationarity_reviewed/short_memory_reviewed/bernoulli_loss_reviewed (boolean).

После независимого просмотра pcap, прочитанных настроек и очередей подготовить JSON с collection_id (имя каталога), reviewer, текстом rationale и trace_review с полями из docs/experiments.md. В обосновании указать анализ MTU, offload, фоновых кадров, вторичных потерь, единиц независимости, задержек у выживших и числовой расчёт main_bandwidth_fraction по отдельному наблюдению обычной нагрузки. Не устанавливать флаг независимости только по отсутствию автокорреляции. Сохранить JSON и использованные дополнительные первичные свидетельства в каталоге сбора. Для решения применить команды (пути от корня):

```sh
docker run --rm --network none -v "$PWD:/bench" -w /bench wswt-bench-analyzer:dev python -B docker/diagnostics/calibration_report.py package "$RUN" "$REVIEW" "$ENVIRONMENT"
make calibrate ARGS="--kind real --input $RUN/publication/input.json --output $RUN/calibration-report.json --environment $ENVIRONMENT"
```

Сверяются снимки контекста и исходников до и после сбора. При несовпадении, обрыве или потере кадров capture папка содержит диагностику; повтор требует нового каталога. Успех shell означает завершение сбора. Приёмка требует отдельного расчёта и независимого ревью.
