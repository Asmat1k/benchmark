# Запуск подготовленного стенда

Основной эксперимент запускает пользователь. Подготовка и короткие проверки не являются основным сбором.

Из корня репозитория, с подключённым питанием и открытой крышкой:

```sh
SERIES_TLS_DIR=build/series-tls-stage2._n__udb0 caffeinate -ims make experiment SERIES_DIR=results/main/final-20261115 ALLOW_REAL_EXPERIMENTS=yes
```

Перед началом команда проверяет питание, крышку, свободное место, Docker VM, образы, TLS, исходники и расписание. `results/main/final-20261115` содержит заранее подготовленные 240 назначений, допуск и снимок исходников. Не менять исполняемые файлы, образы, параметры или сертификат во время серии. Все изменения связываются хешами фактического дерева; снимок не выдаётся за чистый Git-коммит.

Отдельный отказ сохраняется, после успешной очистки выполняется следующее назначение. Прежние назначения не повторяются. Если сбор был прерван, та же команда продолжает оставшиеся назначения; текущий оборванный запуск сохраняет соответствующий статус. Общий бюджет 15 часов отсчитывается от первого начала сбора и сохраняется при продолжении. При недоступности Docker, невозможности очистить собственные ресурсы или занятой подсети команда завершится с причиной; чужие контейнеры не удаляются.

После завершения или остановки автоматически строится отчёт, когда измерительные контейнеры завершены. Открыть `results/main/final-20261115/derived/report.md`; рядом `analysis.json`, `runs.csv`, `rtt.csv`, графики PNG/SVG/PDF и контрольные суммы. Статус каждого назначения виден, включая незапущенные, отклонённые и оборванные. Доступные частичные наблюдения отделены от достоверных полных измерений. Пропуски наблюдений не выдаются за измеренные потери; лаг не фильтрует данные.

При полностью завершённой достоверной сравнительной серии доступны парные расчёты по всему плану. Неполнота не заменяется выводом по удобным завершённым парам. Сбор является исследовательским на фактическом стенде; прежние failed и невыполненные контрольные стадии сохраняются.

Для повторного построения отчёта после завершения измерений:

```sh
make analyze SERIES=results/main/final-20261115
```

Если отчёт не построился автоматически, причина сохраняется в `analysis.stderr.log` и `analysis-exit.json`; прежний `derived` после неуспешного анализа не считается новым отчётом. Для исторических неполных серий предусмотрен явный `ARGS=--all-outcomes`.

Снимок допуска действует в указанном в `admission.json` временном окне, достаточном для сегодняшнего запуска. Если запуск перенесён за это окно или исходники изменились, подготовить новый каталог, сохранив прежний:

```sh
make exploratory-prepare SERIES_DIR=results/main/final-next ENVIRONMENT=results/verify/measurement/resilience-20261115/context.json SERIES_TLS_DIR=build/series-tls-stage2._n__udb0
```

Промежуточный снимок браузера создаётся каждые две секунды при его отзывчивости. При жёсткой аварии состояние после последнего успешного снимка может отсутствовать; возраст последнего снимка и неизвестные результаты остаются видны в данных.
