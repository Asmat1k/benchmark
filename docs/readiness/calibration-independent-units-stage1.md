# Зависимость калибровочных RTT: решение перед этапом 2

Это предложение методики, не принятый протокол и не результат эксперимента. Ограничитель UDP catch-up не устанавливает независимость RTT.

## Что поддерживается сейчас

`acceptance.calibration` строит интервалы медиан по отдельным сообщениям шести latency-подсерий и разности с двумя baseline. Для диагностики `dependence` получает RTT в исходном порядке ответов. Сортировка используется отдельно для рангов. При подозрительном lag1 хотя бы одной подсерии или `independent_units=false` статус inconclusive, если ранее не установлен failed sender. Флаг true не отменяет диагностику. Контракт не содержит session_id/независимых повторений; `calibration_report.package` читает ровно один каталог. Конкатенация повторений, подмена 10000 RTT сорока медианами или несколько вызовов package этого не исправляют.

В исторической calibration.ZQRTHB2H lag1=0.073–0.753. Нет основания применять IID-интервалы к этим сообщениям или оценивать независимость на отсортированных RTT. Новая регрессионная проверка `test_calibration_dependence` закрепляет inconclusive даже при true. Обработчик статистически не «сломался»: он обнаруживает нарушение своей предпосылки. Исправление схемы preliminary и pacing — программные изменения; смена единиц анализа — научное решение.

## Конкретный вариант для согласования

Предлагается оценивать **медиану межсессионных сдвигов медианных RTT**, условных по вернувшимся echo. Это другая величина, чем разность медиан распределений отдельных сообщений, и её нельзя вводить молча.

До первого сбора зафиксировать ровно **40 независимых сессий**. Каждая содержит весь существующий calibration layout: 14 подсерий по 10000 ID, 256 байт, 100 Гц, и четыре saturation по 90000 отправок/72 с с центральным окном61 с. Не сокращать и не добирать по промежуточным результатам. Шесть latency-подсерий: baseline-before, четыре профиля в заданном протоколом порядке, baseline-after. Остальные восемь echo-подсерий остаются для раздельных directional loss denominators. Seeds направлений и сессий различны и публикуются в неизменяемом расписании до измерений; правило их получения должно быть реализовано в будущем коллекторе, текущий shell повторяет один seed-план.

Операционное определение независимой единицы: отдельная сессия в отдельный заранее назначенный день, в одном фиксированном двухчасовом окне суток на выделенном стенде; 40 дат назначаются до старта. Между сессиями остановлены все измерительные процессы; каждая создаёт свежие compose/endpoint/probe-процессы, пустые очереди, новые tags, фиксированные ресурсы и тот же принятый environment. Это снижает общие кратковременные влияния, но **не доказывает** независимость дней от общего host/нагрузки/тренда. Предпосылка независимости сессий требует предметного обоснования и проверки traces/resources; если обеспечить её нельзя, дизайн не даёт допуска. Пропущенная дата или технический отказ не заменяются удобным днём без нового зафиксированного решения; все 40 записей остаются в inventory, неполная серия inconclusive. При нарушении среды/целостности — STOP, без автоматических повторов.

Для сессии j вычислить медианы всех вернувшихся RTT в каждой latency-подсерии, сохранив исходный временной порядок для диагностики. Для каждого профиля p получить две парные величины:

`D[j,p,b] = median(RTT[j,p]) - median(RTT[j,baseline-b])`, b=before/after.

Единица вывода — целая сессия, n=40, не 400000 сообщений. Для каждой из восьми последовательностей D сохранить порядок сессий; раскрыть lag1 и линейный тренд, применить ту же подозрительную границу `2/sqrt(40)`. Отсутствие флага не доказывает IID; выявленный флаг или необоснованная независимость дают inconclusive. Внутрисессионная зависимость RTT остаётся опубликованной диагностикой и не маскируется, но интервалы на отдельных сообщениях больше не являются основанием допуска.

Для вывода предложен тот же принцип точного рангового интервала медианы независимых единиц: на каждую из восьми проверок alpha=.05/8=.00625, Bonferroni для семейства. При n40 взять [D_(11), D_(30)] в отсортированной **копии** вектора; его биномиальное покрытие 0.9977785662≥0.99375. Все восемь интервалов должны целиком лежать в target±2 мс (target20/80). Широкий/неопределимый интервал — inconclusive; без добора, прореживания, замены хвостов или переупорядочивания диагностики. Это предложение расчёта, **не реализованный новый gate**. Принцип ранговых границ описан [NIST](https://itl.nist.gov/div898/software/dataplot/refman1/auxillar/mediancl.htm); биномиальная CDF — [SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binom.html). Число40, дневная организация и семейство восьми сравнений — проектные решения данного предложения, источники их не предписывают.

ID/payload/tag/pcap/counter/resource/sender-v2 проверки сохраняются для каждой сессии. Directional loss остаётся отдельным gate: 99% Clopper–Pearson на фактически вошедших ID допустим только при обоснованной модели независимых Bernoulli netem drops; общие переполнения/зависимые потери нельзя объявлять iid. Автоматически объединять 40 сессий в один loss CI нельзя. До реализации нового формального gate отдельно зафиксировать множественность loss-проверок и правило совмещения с RTT-семейством; текущий контракт не заявляет единого семейного уровня для latency+loss. Численные допуски 1%/0 drops/±2 мс/9–11 Мбит/с не менять.

Сохранять каждый полный исходный каталог без изменений: probe.json со всеми sent/reply ID и временами, pcap/log, qdisc, saturation windows, контексты, source inventories, seals; наверху отдельный session ledger (порядок/даты/seeds/статусы/пути/SHA256), таблицу медиан и D, diagnostics в исходном порядке и ранговые индексы. Неполный набор либо несоответствие первичным файлам не допускается. Новые derived файлы создаются отдельно, исторические материалы не изменяются.

По существующему коду сбор одной сессии занимает30–35 минут: 14×102с +4×72с и setup. Предложенный объём —20–24 часа фактического сбора, распределённые на40 дней. Это оценка, не выполненный запуск. Не запускать сорок повторов текущего shell: он ещё не поддерживает этот дизайн и расчёт.

## Необходимый выбор пользователя

1. Согласовать изменение оцениваемой величины на медиану межсессионных парных сдвигов, фиксированные40 дневных единиц и их предпосылки. Тогда отдельная работа до экспериментов: утвердить версию протокола, loss-множественность, расписание/seeds, входной контракт и обработчик, проверить на искусственных зависимых/независимых сессиях. Это методическое изменение, не оставшийся баг этапа1.
2. Сохранить прежнюю величину (разность медиан сообщений). Тогда нужен отдельно согласованный метод интервалов для зависимого процесса и обоснование его предпосылок; текущие IID-интервалы использовать нельзя. Произвольный bootstrap/HAC/выбор длины блока здесь не внедрён.

До выбора и реализации принятой методики полная calibration остаётся заблокированной. Новая qualification проверяет только sender и не разрешает calibration автоматически. Дополнительная трассировка macOS не является условием решения.
