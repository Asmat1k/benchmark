# Изменения после D6

Основание работы — [исходная независимая рецензия](reviews/01-audit.md). Координатор `/root`, аудитор `/root/auditor`. Исполнители `/root/diagnostics` (UDP), `/root/generator` (таймер, нагрузка), `/root/admission` (допуск и воспроизведение). Независимые рецензенты `/root/verifier` и `/root/admission_review`. Для всех ролей запрос model/effort унаследован без override; подтверждённые значения неизвестны.

| Исходная проблема | Изменение | Где смотреть проверку |
|---|---|---|
| Часы страницы возвращали сводку без первичных времён | Из защищённой страницы получаются 100001 последовательное показание performance.now(). Сборщик заново вычисляет разности и сохраняет их исходные значения для проверки отчёта | [Реальный короткий сбор](../../results/verify/diagnostic/), [регрессии](../../results/verify/readiness/generator-dev/) |
| Для метрик генератора отсутствовал путь от браузера до отчёта | Появились диагностические расписания 20 и 100 Гц, чтение слотов, выборок ресурсов и очередей маршрутизатора, расчёт относительно фактического CPU limit | [Передача исполнителя](../../results/verify/readiness/generator-dev/handoff.md) |
| Анализ калибровки принимал данные извне без реального сборщика | Добавлены отдельные UDP-подсерии для задержки и потерь, сбор pcap обоих направлений, сверка ID, проверка drops по tc и измерение полосы в центральном окне saturation. После R1 каждой подсерии присвоена метка, проверяемая в pcap | [Инструкция](../../docker/calibration.md), [фиксация R1](../../results/verify/readiness/calibration-dev/r1-review-manifest.json) |
| Отчёт воспроизведения можно было предъявить к другому freeze; новое отсутствие результата получало историческую причину | Добавлены привязка к конкретному freeze, сравнение повторных данных по допускам и причина gate_report_not_provided для отсутствующего отчёта | [Проверки допуска](../../results/verify/readiness/admission-dev/), [контракт](../experiments.md) |

Все правки относятся к текущей рабочей версии. Исторические D0–D6 и исходные учебные отчёты сохранены. Сведения об итерациях и границах приёмки см. в [рецензиях](reviews/).

После повторного ревью R2 генератор требует обе обязательные стороны на обеих частотах в одном отчёте, пересчитывает значения из соответствующего raw и сверяет идентичность выбранного run. Отдельный тест подмены ENV подтвердил, что ранее существовавший validate_raw уже отклонял подмену. При prepare файлы теперь проверяются до публикации; повтор может восстановиться при совпадении исходного ledger. Заморозка отвергает ссылку на изменяемый schedule.json, включая hardlink.

Исправления зафиксированы локальным коммитом `d1573e82d7b61d01fb9df88f52469f256031f1d3` поверх D6. Изменено 20 файлов кода, тестов и эксплуатационной документации. [Ревью сборщиков](reviews/02-recheck.md) и [ревью допуска](reviews/03-admission.md) фиксируют границы проверки. Семь из семи тестов контроллера прошли на стабильной копии с историческими fixtures. Первую попытку затронули параллельные изменения source hashes; следующая копия не содержала двух исторических наборов raw. Все три журнала сохранены, [успешный повтор](../../results/verify/readiness/host/controller-fixtures.json).

Текущий допуск UDP sender — [v2](sender-quality-v2.md); исторические оценки every-slot сохранены. Ретроспектива timing не закрывает полную calibration и оставшиеся gates.
