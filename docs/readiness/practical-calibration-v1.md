# Практическая калибровка observed-profile-check-v1

14 ноября 2026. Зафиксированный до новых подтверждающих измерений контракт. Это проверка наблюдённого периода; confidence interval и гарантия будущей стационарности не заявляются. Исторические failed не переоцениваются как подтверждающие passed. Основной сравнительный анализ Q/S/U, парный дизайн, uncertainty и контроль полноты не меняются.

Сбор неизменен: 14 echo-серий по 10000 плановых слотов, 256 байт, 100 Гц, и четыре saturation >=60 с (loss0/1% × forward/reverse). ID/grid/tag/source/ENV/TLS, pcap/counters, zero capture drops, MTU/offloads, отсутствие неожиданных overflow, seed/readback/backlog и browser bandwidth <10% обязательны. Reviewed=true требует явной проверки и rationale; observed_period_reviewed=true не выводится из отсутствия ACF-флагов.

Для шести baseline/latency-серий публикуются все 20 окон по 500 плановых ID: число вернувшихся и медиана всех их реальных RTT. Пустое окно означает failed. Envelope [min(profile)−max(baseline), max(profile)−min(baseline)] для каждого из двух baseline должен целиком находиться в target±2 мс. Это observed range. ACF RTT/survival, fitted drift и признаки suspect сохраняются как диагностика, но не являются тестом предпосылок CI в этой версии.

Потери: все 16 directional before/after наблюдений имеют полные entered/dropped IDs и реальные знаменатели. Loss0 требует drops0; loss1 требует .005≤drops/entered≤.015 (сравнение целыми: entered≤200*drops≤3*entered). Бюджет ±.5 п.п. на направление удерживает наблюдённое отклонение составной потери от .0199 менее 1 п.п.; это арифметика counters, а не доказанная погрешность основного сравнительного S. Расположение drops публикуется. Все четыре capacity должны быть 9–11 Mbit/s.

Sender: ordered complete IDs, конечные времена, сетка 10 мс, отсутствие ранних отправок, monotonic и spacing≥2.5 мс (допуск округления 1e-8 мс), late(lag≥10 мс)≤1%, burst≤4 в (t−10,t] мс. Legacy absolute maxlag50 мс остаётся для udp-sender-v2 и qualification; в новой калибровке maxlag публикуется без самостоятельной браковки. Средняя частота описательна: ±.1 Гц с 20 на 100 Гц не переносится.

Дополнительный observed proxy: IDmod5 задаёт пять подпоследовательностей по 2000 слотов; для каждой проверяются все 801 скользящих окон по 1200 слотов. В каждом окне sender lag≥50 мс отмечает overdue; бюджет ≤12. На loss0 также проверяется union(overdue, known receive после planned+100 мс)≤12, unknown=0. На loss1 lag-проверка остаётся полной, known deadline union является нижней границей, unknown публикуется отдельно, включая upper bound if all unknown bad. Все counts, фазы и нарушенные окна сохраняются. Получение точно в 100 мс timely. Отсутствующий RTT не восстанавливается.

Это proxy при нагрузке UDP100Hz, не replay браузера20Hz и не оценка причинного эффекта TCP/QUIC. Перекрывающиеся окна не независимы. 500 мс pause+catchup2.5 мс даёт [13,12,12,12,12] и failed; 499 мс может пройти. Правило ограничивает долю отмеченных слотов, не максимальную паузу. Редкая пауза на границе записи также может пройти: ограничение раскрывается, новый endpoint threshold без обоснования не добавляется.

Для всех14 серий сохраняется описательная p99-разбивка nearest-rank: ties в body, tail строго выше p99, обе доли по returned и planned, все tail ID/RTT, missing ID отдельно. Ни tail, ни missing не удаляются; sender lag не вычитается из RTT. Tail≤1% по построению не доказывает долю причинно затронутых слотов.

Legacy IID и circular-block-medians-v1 сохраняются как отдельные вычислительные пути с прежними критериями, не становятся актуальными reports нового source. Новый packager требует совпадения сохранённого плана с текущим, seals/source/ENV и независимого collection-specific review. Шесть ранних gates, qualification и BW требуют отдельных applicability capsules, новые source-bound reports нельзя получить заменой hashes старых.

План проверки: meaningful unit/regression нового и legacy пути; отдельный независимый diff/result review; source release/inventory; ранние gates и проверка applicability qualification/BW; одна новая заранее фиксированная calibration без добора; integrity review до публикации; browser generator WS/WT-S/WT-D на20/100Hz. Цель этапа4: восемь passed, aa/monitoring not_run, final=false, verify exit2. Дальше последовательно A/A → monitoring → pilot → power/обоснование n → final verify/freeze/independent reproduction → main≤15ч, по prerequisites проекта. Все команды с возможным временем>5мин запускает пользователь по одной.
