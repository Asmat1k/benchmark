Рецензент /root/calibration_review. Запрошены унаследованные model/effort, подтверждённые значения неизвестны. Проверен сбор results/verify/diagnostic/calibration.ZQRTHB2H на исходном commit 724d491783f7bfbc18d9ec69482b13888fff75d9. Сбор с 2026-11-13 11:07:03Z до 11:36:28Z, exit 0. Проверка только offline, исходные файлы сохранены.

Данные целостны. Все 141 ссылки captured.json совпали по SHA256. context-before и context-after совпадают, равно как оба inventory источников. Readback всех 18 подсерий содержит требуемые delay/loss/rate/limit. Для каждого направления отдельный seed. В начальном router-links.txt четыре проверяемых offload отключены. MTU 1500 проверяется штатным setup_links; все UDP-кадры в echo pcap имеют 298 байт на уровне Ethernet, без IP fragmentation. Дубликатов ID и чужого payload/tag не обнаружено, оба направления содержат соответствующие датаграммы. В журналах capture указано 0 packets dropped by kernel. ## Блокирующие результаты

1. **Сетка 100 Гц нарушена во всех 14 echo-подсериях.** На каждую из 10000 отправок приходятся от 20 до 150 записей с t_send_ms ≥ t_plan_ms+10. acceptance.probe_records требует каждую отправку внутри собственного 10-мс слота. Полный вход calibration не проходит это требование. Исходные времена сохранены, исправлять их задним числом нельзя.
2. **r20p1-before не проходит сверку drops.** Прямые UDP ID дают 102 потери из 10000, обратные — 88 из 9898. Delta tc forward drops=104. Доставлено 9905 netem-пакетов и 2949898 байт, что точно разлагается на 9898 UDP Ethernet-кадров по 298 байт и 7 кадров по 42 байта. В pcap присутствует ARP. Совокупный счётчик учитывает служебные кадры, а анализатор сверяет его только с UDP ID. Это объясняет вероятное происхождение лишних двух drops, но имеющийся ingress capture не доказывает идентичность потерянных egress ARP. Присваивать их UDP нельзя.
3. **Независимость RTT не установлена.** Lag1 от 0,073318 до 0,753319, во всех подсериях выше диагностического порога примерно 0,02. Расчёт узкого рангового интервала на последовательных сообщениях не подтверждает точность на независимых единицах. Требуется отдельный заранее заданный дизайн/решение, критерий не ослаблен.
4. Доля полосы обычной браузерной нагрузки не измерена данным UDP saturation. Для trace_review.main_bandwidth_fraction требуется отдельное наблюдение. Число из заданной конфигурации не является этим наблюдением.

Итог — **калибровка не принята**. Фактический сбор дал полезные первичные наблюдения, но не подтверждает полный gate passed. Code exit 0 относится к сбору. Для нового запуска нужно предварительно устранить смешение служебного и UDP accounting, обследовать причины пропуска 10-мс слотов и определить независимые единицы наблюдения. Повторную длинную серию рецензент не запускал.
