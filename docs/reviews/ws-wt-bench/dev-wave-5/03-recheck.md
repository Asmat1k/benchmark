Минимальный исправленный контракт может оставить текущие SHA256 и файловые графы. На входе реального исполнения необходимо один раз проверить полную цепочку, включая предоставленные извне freeze, reproduction, pilot и power для main. Дальнейший быстрый путь должен привязываться к конкретному результату этой проверки, выданному самим исполнителем, и проверять текущее содержимое всех канонических зависимостей. Состав evidence должен определяться схемой типа и ссылками из первичных материалов; произвольный список внутри предъявленного отчёта сам по себе не является результатом проверки. Дешёвые проверки kind/gate/source/ENV/status, предметных связей и synthetic-признаков сохраняются. Прямой next/record без соответствующего контекста, выданного после глубокой проверки, должен безопасно отказать либо провести первичную полную проверку. Подход с одним управляющим процессом на серию и полной проверкой при каждом новом/возобновлённом сеансе укладывается в эти условия. Новая инфраструктура подписи или удостоверения личности не требуется.
