# Подготовка, запуск и продолжение

Основной сбор запускает пользователь. Ни подготовка допуска, ни короткий smoke не запускают основной эксперимент. Все команды выполняются из корня репозитория.

Для обычного запуска используйте два скрипта из корня проекта:

```sh
./scripts/prepare-experiment.sh
./scripts/start-experiment.sh
```

Первый выполняет сборку и короткие проверки, создаёт новую серию с отдельным TLS-сертификатом и сохраняет её путь в `build/latest-experiment` только после успешной подготовки. Второй запускает последнюю успешно подготовленную серию в фоне через `nohup`, на macOS — с `caffeinate`; журнал дописывается в `SERIES/overnight.log`. Повторный вызов продолжает оставшиеся назначения; одновременно запускать его несколько раз не нужно. После запуска проверьте журнал: ошибки допуска и среды могут остановить фоновый процесс сразу.

Подготавливайте серию непосредственно перед сбором: допуск действует 24 часа с подготовки, а бюджет 15 часов отсчитывается с первого старта и включает паузы. Для продолжения используйте только второй скрипт; первый создаёт новую серию.

## Сборка и короткие проверки

Нужны Docker Compose, Make, Git и Python 3 на хосте. Закреплённая сборка — native Linux ARM64; текущий допуск рассчитан на Docker VM 2 vCPU / 4 ГБ. Подсети `172.28.10.0/24` и `172.28.20.0/24` должны быть свободны. Для длительного сбора на Mac нужны питание, открытая крышка и минимум 10 ГБ свободного места на хосте и в VM.

```sh
make build                 # четыре образа; проверки TypeScript/Go при сборке
make smoke                 # TLS и сетевой путь
make measurement-smoke     # короткое измерение WS/WT-S
make docker-test           # Python-инструменты Docker без измерительной сети
```

## Подготовка новой серии

Команды выполняются из корня проекта. Для следующей серии задайте новые имена `CHECK` и `SERIES`; существующие измерения не перезаписываются. Сертификат общий для всей серии. Короткий проверочный запуск создаёт `context.json` фактической сборки.

```sh
export SERIES_TLS_DIR="$PWD/build/series-tls"
CHECK=results/verify/measurement/check-001
SERIES=results/main/experiment-001
mkdir -p "$SERIES_TLS_DIR"
docker run --rm --network none -v "$SERIES_TLS_DIR:/out" --entrypoint testcert wswt-bench-server:dev /out

docker run --rm --network none -v "$PWD:/bench" -w /bench wswt-bench-analyzer:dev python -B -m execution.schedule smoke "$CHECK" --blocks 1 --sessions 1 --baseline
make measure SERIES_DIR="$CHECK" RUN_INDEX=0
make exploratory-prepare SERIES_DIR="$SERIES" ENVIRONMENT="$CHECK/context.json" SERIES_TLS_DIR="$SERIES_TLS_DIR"
```

Допуск сохраняет расписание, исходники, среду, TLS и их хеши. После изменения кода/образов или истечения срока допуска нужна подготовка нового каталога. Не пересоздавайте сертификат уже начатой серии.

## Основной сбор и результаты

**Следующая команда запускает основной эксперимент с бюджетом до 15 часов**; подготовка выше его не запускает. На Mac `caffeinate` предотвращает сон; на Linux запускайте тот же `make experiment` без `caffeinate -ims`.

```sh
caffeinate -ims make experiment SERIES_DIR="$SERIES" ALLOW_REAL_EXPERIMENTS=yes
```

Та же команда продолжает оставшиеся назначения после прерывания без повторов и добора. Отдельный отказ сохраняется, затем после очистки выполняется следующее назначение; общая неисправность среды или неудачная очистка останавливает сбор. Предел одного запуска — 360 с, аварийной очистки — 30 с. Checkpoint создаётся каждые 2 с при отзывчивом браузере; после жёсткой аварии последние несохранённые данные могут отсутствовать.

Отчёт строится автоматически после освобождения измерительных контейнеров. Все назначения, включая отклонённые, оборванные и незапущенные, видны в `$SERIES/derived/report.md`. Рядом JSON, CSV с ID/RTT/лагом, графики PNG/SVG/PDF, а для полной серии — парные таблицы и bootstrap. Неизвестные данные не выдаются за измеренную потерю. Повторный анализ:

```sh
make analyze SERIES="$SERIES"
# Для исторической неполной серии: добавить ARGS=--all-outcomes
```

Исторические статусы calibration/generator failed и A/A partial сохранены в политике; текущий режим исследовательский, без заявления полной приёмки или мощности 80%. Многочасовая перекалибровка не является условием этого пути. Старые строгие интерфейсы `calibrate`, `generator`, `timer`, `aa`, `monitoring`, `pilot`, `power`, `verify`, `freeze` остаются отдельными командами Make.


Если автоматический анализ завершился ошибкой, причина находится в analysis.stderr.log и analysis-exit.json. Прежний derived после неуспешного анализа не считается новым отчётом.
