## Переданные компоненты

- `src/analysis/inference.py`: полное n/ties/sign, стабильный Holm4, exact binomial rank CI, mean paired block bootstrap и отдельные решения/барьеры.
- `src/analysis/metrics.py`: nearest-rank Q/p50/p99, S/U по всем слотам, штрафной p95 с +∞, события и CPU/lag/queue diagnostics.
- `src/analysis/analyze.py`: строгая проверка всей серии, mandatory `validate_raw` каждого выбранного прогона до расчётов; пары только внутри series/session/profile/block/attempt; отказ на дубликаты, недостающие стороны/attempts/raw, mixed versions/seeds, незавершённую серию и невоспроизводимый audit. Null не удаляет блок или профиль. Replacement audit сохраняется отдельной таблицей. Вывод пересоздаётся после успешного расчёта; старый derived при отказе остаётся прежним.
- `src/analysis/plots.py`: Q/S/U/order/session/условная ECDF, парные CI и WT-D descriptive CI. PNG300dpi/SVG/PDF, plotting CSV, rcParams/style/font hashes, backend/размеры, фиксированные metadata. Автоматической статистики Seaborn нет.
- `src/analysis/test_analysis.py`, `fixtures/references.json`, `synthetic.py`: заранее известные эталоны, перебор знаков, сгруппированный контрпример message bootstrap, проверки integrity/null/audit и обычный Python CLI с offline повтором. Generator создаёт явно синтетическую diagnostic series, не сетевой прогон.
- Make `analyze SERIES=...`/`analysis-test`, `docker/analyze.sh`, `.github/workflows/checks.yml`. Сеть analyzer отключена; measurement lock предотвращает одновременную работу с измерением. CI собирает закреплённый образ, проверяет схемы/статистику, сохраняет network smoke как not_run при отсутствии допущенного хоста.
- README, docs/analysis.md и execution-matrix.md содержат интерфейс/точные инструкции и раздельные статусы. D4 реализация завершена, независимая приёмка ожидается; experimental not_run/deferred_by_user.

## Воспроизведение и продолжение

Из корня проекта с готовым `wswt-bench-analyzer:dev` выполнить `make analysis-test`. Полный повтор штатного анализа на новом synthetic каталоге описан в [docs/analysis.md](../analysis.md#синтетическое-воспроизведение):

```sh
docker run --rm --network none -e PYTHONDONTWRITEBYTECODE=1 -v "$PWD:/bench" -w /bench wswt-bench-analyzer:dev python src/analysis/synthetic.py build/d4-reproduction --blocks 2
make analyze SERIES=build/d4-reproduction
```

Первую команду выполнять для отсутствующего каталога. Исходный accepted synthetic evidence при этом не перезаписывается. JSON бесконечности строго строки `+inf`/`-inf` по D0; отсутствие null, CSV inf/NA. Сохранённые NPZ содержат реальные10000×n block indices. Seed branch6 зарезервирована для bootstrap; направление потерь, schedule/nonce и будущая power должны использовать другие ветви. State/seed/profile/block order и hashes сохраняются в provenance. Проверяющий может сверить finite числа с1e−10 и целые/решения/ID/indices точно; автоматический тест выполняет повтор расчёта. Архивы реальных исходных данных не изменены.

Функции статистики, проверенные контракты анализа и контрольные fixtures подготовлены для возможной будущей D5. По последующему указанию пользователя текущая работа заканчивается после полноценной D4, её независимой приёмки, коммита координатора и cleanup; D5 не начинается. Потребители A/A/monitoring в будущей работе должны отдельно поддержать соответствующий design и95% интервалы, а не подавать их на comparison CLI. Средовая и экспериментальная calibration, saturation, generator20/100Гц, A/A, monitoring, официальный pilot/power, final verify/freeze и main не запускались и остаются not_run/deferred_by_user. Общего победителя по профилям нет, независимость блоков и риск редких отказов synthetic тестами не доказываются.

Все созданные контейнеры запускались с `--rm --network none` и завершились. Ранее существовавший `ai-grepa-qdrant-1` не менялся. __pycache__ удалён. Изменения остановлены для независимого ревью; рецензент не должен считать эту самопроверку приёмкой разработки.

## Точечное исправление R4a

В [повторной рецензии](../reviews/ws-wt-bench/dev-wave-4/02-recheck.md) R1–R7 подтверждены, кроме R4a: семантическая проверка повреждённого локального schedule исключённой стороны блокировала разрешённую hash-замену. Условие в analyze.py уточнено только для конкретного proof member с reason=hash. Его bytes не исправляются и не объявляются валидным расписанием; identity, proof.files/context/identity, evidence SHA и точное воспроизведение D3 detect по-прежнему обязательны. Независимый audit schedule, transaction, прочие архивные стороны и все активные raw проверяются без исключения.

Новый regression `test_r4a_hash_corrupted_schedule_diagnose_replace_analyze_cli` исполняет настоящие `violation.py → replace.py → analyze.py` как обычные CLI. В локальном schedule одной старой стороны master_seed изменён20261108→20261109 без переподписания. Diagnose выдал hash/hash mismatch, replace сохранил весь старый блок и назначил новую попытку; анализ полной synthetic замены прошёл, audit.csv содержит1 запись с reason=hash. Далее семь независимых подмен (источник после proof, evidence, identity, независимый archive, transaction, sibling и переподписанный active snapshot) отвергнуты с сохранением прежнего derived. Целевой тест прошёл за19.038с; журнал в [recheck2/r4a-tests.txt](../../results/verify/analysis/recheck2/r4a-tests.txt).

Отдельно повторены целевые R1/R3 normal CLI regressions (перестановка/дублирование каталога и усечение текущего плана). Полный16-тестовый набор и научные эталоны уже прошли у исполнителя и независимого рецензента; повтор графиков и всего анализа для неизменённых выходов не выполнялся. Ранее сохранённые source hashes описывают соответствующие исторические итерации; текущие hashes затронутых файлов и новые checks/evidence находятся в recheck2.
