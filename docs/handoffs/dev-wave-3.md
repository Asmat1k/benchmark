Вход: main `3338f5431ac230561a7c094f319c4975e458c786`. D0–D2 приняты и коммитнуты. На входе у этого исполнителя уже находилась почти готовая незакоммиченная D3 предыдущего исполнителя; .agents/plan/ — пользовательский каталог, не входит в изменения волны. Исполнитель завершения: `/root/dev_wave_3_implementer_routed`. Запрошены model `gpt-6.1-sol`, reasoning `high`; подтверждённые значения неизвестны, инструмент их не предоставил. Предыдущий исполнитель `/root/dev_wave_3_implementer` был остановлен координатором.

## Реализовано

- src/client/src/{measurement,measure-page,timer}.ts: страничные часы, заранее все warmup/measurement слоты/рамки, абсолютная сетка, без catch-up/ожидания echo/write; timestamp непосредственно перед API, exact complete echo, deadline/horizon включительно, все исходы/причины, duplicate/corrupt/unknown IDs, bounded queues и disconnect. WT-D дополнительный адаптер с capability check. timerResolution реализован, реальная калибровка не запускалась.
- src/runner/measure.ts: secure page и фиксированный запуск браузерного измерителя, запись после завершения, trust/Chromium args/security metadata. Node не измеряет RTT.
- src/server: раздельные phase counters, активные сеансы и атомарный snapshot по SIGUSR1; счётчики не заменяют browser receive. Go unit test покрывает invalid/write error/echo и разделение фаз.
- src/analysis/{schedule,raw,record,quarantine,replace}.py: PCG64 seed tree, парные блоки/сессии, preparation/finalization, полная проверка raw, SHA256SUMS, fsync файлов/каталога и атомарный rename. Snapshot расписания внутри каждого нового raw не меняется при замене другого блока. Legacy smoke первого исполнителя ещё использует внешний неизменённый schedule.
- docker/{measure,measurement-smoke,sample,links}.sh и Make: свежие процессы/соединение/qdisc на run, один measurement lock, общий leaf пары, cgroup delta resources раз в секунду, >=5 с pause, единый <=30 с stabilization budget, обе очереди пусты непрерывно >=1 с, CPU сравнён с baseline, server inactive. Partial/quarantine/STOP и audit всей пары. make measure — обычный entry point, pilot/main пока запрещены.
- Замена доказанного hash/config/schema/clock/path нарушения переносит весь блок в audit, сохраняет evidence и прежний schedule, генерирует новый attempt/nonce/seeds и случайное место в queue.json. Неполный лог/OOM/expiry/STOP требуют новой серии, а не замены для продолжения.

## Ограничения и D4–D5

Все экспериментальные gates сохраняют not_run/deferred_by_user. Реальные 200+1200, 20/100 Гц generator capacity, 100000 performance.now, calibration, A/A, monitoring, pilot, power, full verify/freeze/main не запускались. Smoke не доказывает точность таймера/сети или достоверность результатов. Среда D2 допущена только для разработки.

D4 должен вызывать raw.validate_raw до любых метрик и сохранить definitions Q/S/U/null/штраф/полное n/Holm4. D5 получает одиночный run entry point и stop/replacement средства; должен реализовать последовательный диспетчер queue.json, gates и выпуск финального окружения, не обходя STOP. queue.json задаёт оставшийся порядок после замены, исторические run entries и audit не являются активными заданиями. Длительные реальные команды выполняются только отдельным последующим поручением после допуска. Итоговые image IDs локальной сборки D3 записаны внутри smoke provenance; locks D2 остаются историческим baseline и не объявляются образом окончательного экспериментального релиза.

## Исправления после повторного ревью R3a/R5a–c/R6a–b

- R3a: опубликованные environment host/VM/limits сопоставляются с первичными снимками и context; provenance images/build/полный набор lock hashes — с фактическими входами. Переподписанные противоречия VM CPU, лимита, image ID и пустые hashes отклоняются.
- R5a: runtime использует общий docker/measurement-cleanup.sh. После появления SHA256SUMS cleanup больше не пишет диагностические файлы внутрь подписанного snapshot. E2E тест выполняет фактическую shell-функцию с stub compose после настоящего complete exit3, проверяет побайтовый состав quarantine и запускает настоящий relative CLI replace по исходной evidence.
- R5b: замена разрешается по точному перечню технических кодов, без поиска подстрок. Утрата обязательного файла/declared entry, неполные completion/events/resources, OOM, смена контекста и выход за срок leaf имеют отдельный STOP route. diagnose устанавливает STOP также при обнаружении в уже опубликованном raw. Полный raw с воспроизводимыми path/clock дефектами сохраняет replacement route; expiry не классифицируется как clock для замены.
- R5c: proof связан с неизменёнными source manifest, schedule run, полной identity run/attempt/block/session/series, snapshot hashes и контекстом серии. Одновременная подмена run+attempt на чужую пару отклоняется до создания audit или изменения ledger/queue/raw.
- R6a: directory/evidence/source/schedule приводятся к физическим абсолютным путям один раз на границе API. Реальные CLI тесты используют относительный путь и симлинк, host suite использует обычный macOS TMPDIR (/var↔/private/var).
- R6b: mkdir lock заменён advisory lock build/measurement.flock. На Linux её освобождает ядро при завершении процесса. Обнаружено, что native macOS flock не координируется с Docker VM flock; поэтому все владельцы используют Linux lock. macOS CLI делегирует только удержание lock короткому network-none helper; штатный shell entrypoint удерживает helper через stdin/FIFO. Закрытие pipe после аварии освобождает lock. Helper использует готовый analyzer image как техническую среду, только блокируется на stdin и не выполняет анализ, не создаёт трафик, не имеет socket mount/host PID/network или дополнительных privileges. Вычислительный analyzer по-прежнему запускается только до/после browser. Смена image после подтверждения совместимости не требовалась.

Прежние R1/R2/R4/R7 regressions сохранены. Нативный macOS suite и locked Linux suite прошли; D0 fixtures и offline smoke повторены. cross-host-lock.txt содержит фактический ответ `2 busy` при конкуренции host CLI и Docker.
