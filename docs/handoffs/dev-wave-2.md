## Единственный путь

При обычном соединении через internal Docker bridges и статические маршруты до router дошёл ARP; TCP SYN был виден на browser, но отсутствовал в trace router. Internal macvlan оставил TSO/GSO/GRO включёнными после запроса off. Диагностика сохранена в results/verify/path/. На рабочем пути внутри каждого выделенного IPAM /24 временный route-init создаёт пару veth, переносит заданные IP на неё, опускает первоначальный Docker-интерфейс. Router получает два интерфейса, endpoint ровно один. Все измерительные процессы работают без NET_ADMIN, нет host network/PID или опубликованных портов. Краткий помощник с NET_ADMIN и SYS_PTRACE видит PID namespace только своего endpoint, открывает сетевой namespace PID 1 для создания peer. При завершении помощник удаляется. Временное отключение forwarding пересоздаёт router и обе пары, после чего проверяются маршруты и соединения.

[Итоговый запуск](../../results/verify/path/wswt-smoke.rXD6yyAY/) — `make smoke` с exit 0. MTU 1500, TCP/UDP прошли в обе стороны через оба интерфейса, в endpoint виден явный next hop. При прочитанном net.ipv4.ip_forward=0 WSS и WT-S истекли через 2,5 с, после восстановления в 1 Chromium вновь вернул по три точных эхо; отрицательные TLS-пробы прошли. Проверены readback delay/loss/rate/limit/jitter/correlation и разные seed на обоих egress всех четырёх профилей. GRO/GSO/TSO/LRO выключены, счётчики, trace и лимиты записаны. Проверка даёт функциональное свидетельство пути, количественная калибровка отложена. Проект удалён, повторный `make cleanup RUN_DIR=results/verify/path/wswt-smoke.rXD6yyAY` и проверка остатков выполняются независимо.

## Диагностические итерации

Три первых попытки на обычных bridge завершились тайм-аутом навигации 6 с, третья включала одиночную TCP-пробу до 2 с. Две попытки подготовки macvlan/veth остановились на проверке offload/доступа к namespace до прикладного трафика. Первая рабочая пара veth прошла исходный echo и пробу forwarding-off, выявила ошибку восстановления значения окружения. После её исправления две итерации проверили восстановленный путь и затем усиленный JSON readback. Каждый Chromium-сценарий ограничен 45 с, в наиболее полной итерации три сценария — до 135 с активного трафика. Профили применялись без серии сообщений. Пропускная способность, потери и стабильность генератора не измерялись.
