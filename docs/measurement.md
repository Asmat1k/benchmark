# Измеритель и raw

D3 реализует обычный прогон 200 warmup + 1200 measurement слотов и отдельный короткий smoke (1 + 3). Реальные обычные прогоны, калибровка таймера и эксперименты сейчас отложены пользователем. Smoke проверяет соединение, журнал и завершение; он не оценивает точность, потери или производительность.

После `make build` команда `make measurement-smoke` выбирает baseline без добавленных задержки/потерь и создаёт отдельную серию в results/verify/measurement/smoke.*, общий временный leaf для пары, новый Compose project/server/Chromium/connection/qdisc для каждого режима WS и WT-S. Сценарий браузера ограничен 30 с, всего два сценария. Analyzer запускается только до и после измерительной фазы, с отключённой сетью. Все контейнеры своего проекта удаляются, чужие не затрагиваются. Успех smoke дополнительно требует полный точный возврат всех 1+3 рамок в обоих режимах; валидный raw с потерями не означает успешный smoke.

Страница заранее создаёт все рамки и слоты, использует performance.now и абсолютную сетку. Miss не догоняется. API вызов, fulfilled write, первый правильный полный echo различны. Deadline и horizon включительны; повреждённый echo не препятствует последующему correct, duplicate не меняет первый echo. WS bufferedAmount и сумма pending WT writes ограничены 1 MiB. Disconnect сохраняет все оставшиеся слоты. WT-D предусмотрен только при maxDatagramSize >= 256.

Расписание готовится до измерений: `python src/analysis/schedule.py verify results/verify/measurement/NAME`. Параметры по умолчанию — 20 блоков каждого профиля, четыре сессии. --baseline выбирает отдельный loss0 профиль с delay0, rate10 Мбит/с, limit1000 и независимыми seeds; baseline запрещён для pilot/main. PCG64/SeedSequence разделяет series ID, schedule, forward, reverse, nonce и replacement ветви. Воспроизведение требует analyzer с закреплёнными NumPy/Python. `schedule.json` задаёт каждый run и порядок исходных блоков/режимов, `ledger.json` хранит состояние попыток.

Для будущей обычной проверки служит `make measure SERIES_DIR=results/verify/measurement/NAME RUN_INDEX=0`, где RUN_INDEX — индекс в runs расписания. Подготовка отклоняет любой индекс кроме первой оставшейся стороны первого блока queue; публикация обеих сторон удаляет завершённый блок из queue. Для неё обязателен SERIES_TLS_DIR с public/ и server/, один leaf на всю серию. Обычный таймер браузера 90 с рассчитан на 10+60+5 с; это не короткий smoke и сейчас не запускается. Pilot и main отклоняются до запуска. Допуск будущих экспериментальных серий реализуется в D5.

До первого browser context.json фиксирует leaf, host/VM, images, лимиты, configs и locks. До/после каждого прогона и перед следующей стороной контекст сверяется без transient имён процессов. Изменение даёт STOP. Route/MTU/offload после читаются независимо у обоих endpoints/router.

После drain соединение закрывается, выдерживается пауза >=5 с. Затем общий предел стабилизации 30 с: оба netem непрерывно пусты не менее 1 с, сервер не имеет активных сеансов, CPU каждой роли не превышает округлённый вверх максимум её трёхсекундного baseline. Sampler снабжает строки sample_index и end_usec по /proc/uptime (VM), не подменяющие часы браузера для RTT. Каждый интервал <=1.5 с, без разрывов; перед browser и при idle проверяется свежесть последней строки <=1.5 с, финальный отсчёт покрывает конец окна. CPU и throttling считаются по cgroup deltas/wall delta; память и OOM читаются каждую секунду. Провал, OOM, истёкший сертификат или неполный журнал останавливают серию через STOP.

Raw сначала пишется в .partial. После закрытия страницы собираются slots/warmup/events/resources/server, readback сети до/после, provenance образов/locks/build, сертификат, Chromium args и окружение. Manifest связывает эти файлы хешами; schedule.json внутри raw сохраняет неизменную версию задания. Проверяются схемы, hashes, IDs, nonce, число слотов, сетка, timestamps, исходы, counters, путь/qdisc/seeds и certificate validity. Файлы fsync и атомарный rename публикуют каталог raw. Повторная запись того же run запрещена. После SHA256SUMS shell cleanup сохраняет snapshot побайтно: диагностика не дописывается в него. Proof сравнивается с source manifest identity, immutable schedule run и контекстом серии до любого переноса. CSV в D4 будет derived, не заменой raw.

Неудачная подготовленная попытка сохраняется в quarantine; весь парный блок переносится в audit, ledger получает stopped. При STOP продолжение требует новой версии серии. Высокий RTT, потери, очередь, API failure и disconnect сами по себе не исключаются.

Доказательство создаёт `python src/analysis/violation.py RAW_FOLDER DIRECTORY/schedule.json EVIDENCE_FILE`: оно привязано к run/attempt и hashes, дефект повторно воспроизводится перед заменой. Корректный raw, пустая/чужая evidence не дают замены. Штатная публикация полного raw с заменяемым техническим дефектом создаёт такое доказательство, возвращает exit3 и устанавливает PENDING_REPLACEMENT. Потеря обязательного файла/записи, OOM, изменение среды или expiry устанавливают STOP, включая offline обнаружение уже опубликованного raw. Категории replacement задаются точными кодами, expiry не является заменяемым clock. Замену без STOP оформляет команда `python src/analysis/replace.py DIRECTORY ATTEMPT_ID REASON EVIDENCE_FILE`. Она сохраняет evidence и старое расписание, переносит обе стороны блока в audit, создаёт новый attempt с новыми nonce/seeds/порядком режимов. queue.json фиксирует случайное место замены среди оставшихся planned блоков. Одиночный entry point уже проверяет queue.json. Replace и measure разделяют kernel advisory lock build/measurement.flock внутри Linux VM. На macOS CLI только удержание lock делегирует готовому analyzer image с --network none; shell держит того же idle helper через stdin/FIFO. Helper не выполняет анализ. Закрытие pipe или завершение владельца освобождает lock без stale mkdir; живого владельца вытеснить нельзя. Relative directory и симлинки канонизируются. Replacement journal fsync предшествует переносу; admission блокируется до завершения, повтор той же команды продолжает незавершённый переход или возвращает единственную выполненную замену. Старые run-записи остаются для аудита, их запуск запрещён ledger. Неполный лог и STOP не разрешают замену как способ продолжить остановленную серию.

Историческое raw до resource coverage полей сохраняется без изменений; оно не является evidence текущего полного контракта. Новые tests используют временные синтетические копии.

Offline проверки: `docker run --rm --network none -v "$PWD:/bench" -w /bench wswt-bench-analyzer:dev python -B -m unittest discover -s src/analysis -p 'test_*.py' -v`. Browser/Go тесты выполняются при сборке. Timer diagnostic реализован с инъекцией часов; реальные 100000 performance.now сейчас не запускаются.
